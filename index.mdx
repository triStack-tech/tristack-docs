Tristack runs platforms you build on: **Manifold AI** generates text, and **Tristack CPaaS**
delivers messages to people. You can use one without ever touching the other.

<CardGroup cols={2}>
  <Card title="Manifold AI" icon="brain" href="/manifold/quickstart" horizontal>
    **Text in, text out.** One HTTP API for language models: send messages, name a model
    by alias, read the answer back. Metered per token.

    `POST /v1/manifold/messages`
  </Card>

  <Card title="Tristack CPaaS" icon="tower-broadcast" href="/relay/index" horizontal>
    **Reach a person.** A set of channels sharing one key and one wallet: voice calls,
    transactional email, and one-time codes by WhatsApp or SMS.

    `POST /v1/relay/voice` · `POST /v1/relay/email`
  </Card>
</CardGroup>

## Tristack CPaaS is a set of channels, not a single endpoint

Each CPaaS channel has its own endpoint, request shape and price. They share a key, a wallet
and a project, and nothing else. The API paths still say `relay`, from the product's earlier
name; they are unchanged.

| Channel | Status | Endpoint | Billed |
| --- | --- | --- | --- |
| [Voice](/relay-voice/quickstart) | Available | `POST /v1/relay/voice` | Per character of speech |
| [Email](/relay-email/quickstart) | Available | `POST /v1/relay/email` | Per recipient |
| [WhatsApp](/relay-whatsapp/index) | Available | `POST /v1/relay/whatsapp/otp` | Per code sent |
| [SMS](/relay-sms/index) | Early access | `POST /v1/relay/sms/otp` | Per code sent |

## They are separate platforms, not halves of one

This is worth being clear about up front, because the shared plumbing makes them look more
connected than they are.

<Columns cols={2}>
  <div>
    **What they share**

    - One Tristack account and one dashboard
    - One prepaid wallet: Manifold AI and every CPaaS channel draw from the same balance
    - The same kind of API key (`tsk_live_…`), scoped to a project
    - The same error envelope and the same base URL
  </div>

  <div>
    **What they do not share**

    - Different endpoints, request shapes and responses
    - A separate per-project switch each: enabling one does nothing to the others
    - Separate pricing, on entirely different units
    - Nothing passes between them. Manifold's answer is not spoken down a phone or put in an
      email unless you send it there yourself
  </div>
</Columns>

<Note>
  A key with Manifold AI enabled and Voice disabled calls Manifold and gets
  `403 relay_voice_disabled` from Voice. The switches are per project and per channel.
</Note>

## Which one do you want?

<AccordionGroup>
  <Accordion title="I want a model to answer a prompt" icon="brain">
    That is **Manifold AI**. You send messages and get generated text back, streaming or not.
    Billing is per token, at the model's own rate.

    [Manifold AI quickstart →](/manifold/quickstart)
  </Accordion>

  <Accordion title="I want to telephone people and play them a message" icon="phone">
    That is the **Voice** channel of Tristack CPaaS. You send a list of Indian mobile numbers and the words to say.
    It synthesizes the speech once and calls everyone. You are billed for preparing the
    recording and not for the calls, so reaching five hundred people costs what reaching one
    does.

    [Voice quickstart →](/relay-voice/quickstart)
  </Accordion>

  <Accordion title="I want to send a receipt, a password reset or an alert by email" icon="envelope">
    That is the **Email** channel of Tristack CPaaS. You verify a domain you own with three DNS records, then send
    from any address at it. Billing is per recipient, so one email to fifty people costs
    fifty times one email to one person.

    [Email quickstart →](/relay-email/quickstart)
  </Accordion>

  <Accordion title="I want a model to write the message, then send it" icon="arrow-right-arrow-left">
    That is **Manifold AI and a CPaaS channel, called in sequence, by your code**. Ask
    Manifold for the text, take the string out of the response, and pass it to the channel
    as `text`.

    There is no shortcut that does it in one call, and no hidden coupling: to Tristack CPaaS,
    text written by a model is just text.
  </Accordion>
</AccordionGroup>

## Everything below this line is common to all of them

<Steps>
  <Step title="Create a project">
    A project owns its API keys and its usage. Most teams run one project per app, or one
    per environment.

    [Projects and keys →](/platform/projects-and-keys)
  </Step>

  <Step title="Turn on what you need">
    Manifold AI and each CPaaS channel have their own switch on the project. They are
    independent.
  </Step>

  <Step title="Create an API key">
    `tsk_live_…` for production, `tsk_test_…` otherwise. The full token is shown once, at
    creation, and never again.
  </Step>

  <Step title="Fund the wallet">
    One prepaid balance in paise, drawn on by Manifold AI and Tristack CPaaS alike. A call that cannot be covered
    is refused with `402` before anything is spent.

    [Wallet and billing →](/platform/wallet)
  </Step>
</Steps>

```bash One key, one base URL
export TRISTACK_API_KEY="tsk_live_your_key_here"

# Manifold AI: a model answers
curl https://api.tristack.tech/v1/manifold/messages \
  -H "Authorization: Bearer $TRISTACK_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"nova-micro","max_tokens":256,
       "messages":[{"role":"user","content":"Say hello from Tristack."}]}'

# Voice: a phone rings
curl https://api.tristack.tech/v1/relay/voice \
  -H "Authorization: Bearer $TRISTACK_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"to":["+91XXXXXXXXXX"],"text":"Your delivery arrives between 4 and 6 today."}'

# Email: a message lands in an inbox
curl https://api.tristack.tech/v1/relay/email \
  -H "Authorization: Bearer $TRISTACK_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"from":"no-reply@yourdomain.com","to":["REPLACE_WITH_YOUR_ADDRESS"],
       "subject":"Your receipt","text":"Thanks for your order."}'
```

<Info>
  **Base URL** `https://api.tristack.tech` · **Auth** `Authorization: Bearer tsk_live_…`
  (or `X-Api-Key`) · **Money** every amount is an integer in paise, so ₹1.50 is `150`.
</Info>
