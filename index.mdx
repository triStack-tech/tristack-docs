Tristack runs **two products**. Manifold generates text. Relay delivers messages to people.
You can use one without ever touching the other.

<CardGroup cols={2}>
  <Card title="Manifold" icon="brain" href="/manifold/quickstart" horizontal>
    **Text in, text out.** One HTTP API for language models: send messages, name a model
    by alias, read the answer back. Metered per token.

    `POST /v1/manifold/messages`
  </Card>

  <Card title="Relay" icon="tower-broadcast" href="/relay/index" horizontal>
    **Reach a person.** A family of channels sharing one key and one wallet: a phone call
    today, transactional email today, SMS and one-time passcodes to come.

    `POST /v1/relay/voice` · `POST /v1/relay/email`
  </Card>
</CardGroup>

## Relay is a family, not a single endpoint

Each Relay channel is its own product with its own endpoint, request shape and price. They
share a key, a wallet and a project, and nothing else.

| Channel | Status | Endpoint | Billed |
| --- | --- | --- | --- |
| [Relay Voice](/relay-voice/quickstart) | Available | `POST /v1/relay/voice` | Per answered call |
| [Relay Email](/relay-email/quickstart) | Available | `POST /v1/relay/email` | Per recipient |
| Relay SMS | Not available yet | | |
| Relay OTP | Not available yet | | |

## They are separate products, not halves of one

This is worth being clear about up front, because the shared plumbing makes them look more
connected than they are.

<Columns cols={2}>
  <div>
    **What they share**

    - One Tristack account and one dashboard
    - One prepaid wallet: every product draws from the same balance
    - The same kind of API key (`tsk_live_…`), scoped to a project
    - The same error envelope and the same base URL
  </div>

  <div>
    **What they do not share**

    - Different endpoints, request shapes and responses
    - A separate per-project switch each: enabling one does nothing to the others
    - Separate pricing, on entirely different units
    - Nothing passes between them. Manifold's answer is not spoken down a phone or put in an
      email unless you send it there yourself
  </div>
</Columns>

<Note>
  A key with Manifold enabled and Relay Voice disabled calls Manifold and gets
  `403 relay_voice_disabled` from Relay Voice. The switches are per project and per product.
</Note>

## Which one do you want?

<AccordionGroup>
  <Accordion title="I want a model to answer a prompt" icon="brain">
    That is **Manifold**. You send messages and get generated text back, streaming or not.
    Billing is per token, at the model's own rate.

    [Manifold quickstart →](/manifold/quickstart)
  </Accordion>

  <Accordion title="I want to telephone people and play them a message" icon="phone">
    That is **Relay Voice**. You send a list of Indian mobile numbers and the words to say.
    It synthesizes the speech once and calls everyone. Billing is per answered call, plus a
    one-off charge for preparing each new recording.

    [Relay Voice quickstart →](/relay-voice/quickstart)
  </Accordion>

  <Accordion title="I want to send a receipt, a password reset or an alert by email" icon="envelope">
    That is **Relay Email**. You verify a domain you own with three DNS records, then send
    from any address at it. Billing is per recipient, so one email to fifty people costs
    fifty times one email to one person.

    [Relay Email quickstart →](/relay-email/quickstart)
  </Accordion>

  <Accordion title="I want a model to write the message, then send it" icon="arrow-right-arrow-left">
    That is **two products, called in sequence, by your code**. Ask Manifold for the text,
    take the string out of the response, and pass it to Relay as `text`.

    There is no shortcut that does it in one call, and no hidden coupling: to Relay, text
    written by a model is just text.
  </Accordion>
</AccordionGroup>

## Everything below this line is common to all of them

<Steps>
  <Step title="Create a project">
    A project owns its API keys and its usage. Most teams run one project per app, or one
    per environment.

    [Projects and keys →](/platform/projects-and-keys)
  </Step>

  <Step title="Turn on the products you want">
    Each product has its own switch on the project. They are independent.
  </Step>

  <Step title="Create an API key">
    `tsk_live_…` for production, `tsk_test_…` otherwise. The full token is shown once, at
    creation, and never again.
  </Step>

  <Step title="Fund the wallet">
    One prepaid balance in paise, drawn on by every product. A call that cannot be covered
    is refused with `402` before anything is spent.

    [Wallet and billing →](/platform/wallet)
  </Step>
</Steps>

```bash Three products, one key, one base URL
export TRISTACK_API_KEY="tsk_live_your_key_here"

# Manifold: a model answers
curl https://api.tristack.tech/v1/manifold/messages \
  -H "Authorization: Bearer $TRISTACK_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"nova-micro","max_tokens":256,
       "messages":[{"role":"user","content":"Say hello from Tristack."}]}'

# Relay Voice: a phone rings
curl https://api.tristack.tech/v1/relay/voice \
  -H "Authorization: Bearer $TRISTACK_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"to":["+91XXXXXXXXXX"],"text":"Your delivery arrives between 4 and 6 today."}'

# Relay Email: a message lands in an inbox
curl https://api.tristack.tech/v1/relay/email \
  -H "Authorization: Bearer $TRISTACK_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"from":"no-reply@yourdomain.com","to":["REPLACE_WITH_YOUR_ADDRESS"],
       "subject":"Your receipt","text":"Thanks for your order."}'
```

<Info>
  **Base URL** `https://api.tristack.tech` · **Auth** `Authorization: Bearer tsk_live_…`
  (or `X-Api-Key`) · **Money** every amount is an integer in paise, so ₹1.50 is `150`.
</Info>
