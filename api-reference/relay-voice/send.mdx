<Info>
  `POST https://api.tristack.tech/v1/relay/voice` · Auth: `Authorization: Bearer tsk_live_…`
  or `X-Api-Key: tsk_live_…` · Fields are **camelCase**.
</Info>

Takes a list of Indian mobile numbers and a line of text, speaks the text once, and phones
everybody with the result. It answers `202` as soon as the job is paid for and queued;
dialing happens in the background, because a few hundred recipients is minutes of calling
and no HTTP client should hold a socket open for that.

## Send a request

<CodeGroup>

```bash curl
curl https://api.tristack.tech/v1/relay/voice \
  -H "Authorization: Bearer $TRISTACK_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "to": ["+91XXXXXXXXXX", "0YYYYYYYYYY"],
    "text": "Your delivery arrives between 4 and 6 today.",
    "reference": "order-4417"
  }'
```

```python Python
# pip install requests
import os

import requests

response = requests.post(
    "https://api.tristack.tech/v1/relay/voice",
    headers={"Authorization": f"Bearer {os.environ['TRISTACK_API_KEY']}"},
    json={
        "to": ["+91XXXXXXXXXX", "0YYYYYYYYYY"],
        "text": "Your delivery arrives between 4 and 6 today.",
        "reference": "order-4417",
    },
    timeout=60,
)
if response.status_code != 202:
    failure = response.json()
    raise RuntimeError(f"{response.status_code} {failure['code']}: {failure['error']}")

job = response.json()
# Keep both: jobId to poll, audioId to replay this recording for free later.
print(job["jobId"], job["audioId"], job["estimatedCostPaise"], "paise held")
```

```javascript Node
// Node 18 or newer, no dependencies.
const response = await fetch("https://api.tristack.tech/v1/relay/voice", {
  method: "POST",
  headers: {
    Authorization: `Bearer ${process.env.TRISTACK_API_KEY}`,
    "Content-Type": "application/json",
  },

  }),
});

if (response.status !== 202) {
  const failure = await response.json();
  throw new Error(`${response.status} ${failure.code}: ${failure.error}`);
}

const job = await response.json();
console.log(job.jobId, job.audioId, job.estimatedCostPaise, "paise held");
```

</CodeGroup>

## The one rule

<Warning>
  **Send exactly one of `text` and `audioId`. Never both, never neither.**

  Both is `400 invalid_request`, and so is neither. Accepting both and quietly preferring one
  would mean that a caller who rewrote their message but forgot to drop the old `audioId`
  keeps broadcasting the old recording, and every call looks correct from here.

  `voice` belongs to `text` alone. A stored recording already carries the voice it was spoken
  in, so sending `voice` with `audioId` is also `400 invalid_request` rather than a silently
  ignored field.
</Warning>

## Request

<ParamField body="to" type="string[]" required>
  Indian mobile numbers, at least one and at most **500** per request.

  Any common spelling is accepted and normalized to E.164, so `+91 XXXXX XXXXX`,
  `91-XXXXXXXXXX`, `0XXXXXXXXXX` and `XXXXXXXXXX` are all the same recipient. Spaces,
  dashes, dots and brackets are ignored; anything holding a letter is refused rather than
  guessed at.

  <Note>
    `XXXXXXXXXX`, `YYYYYYYYYY` and `ZZZZZZZZZZ` throughout these docs are placeholders
    standing in for three different recipients, never real numbers. Substitute your own
    before sending: left as-is a request is refused with `400 invalid_phone_number`.
  </Note>

  **Duplicates collapse.** The same number written twice in one request is one call and one
  charge. The `recipients` count and the `calls` array in the response are the deduplicated
  list, in the order the numbers first appeared, so you can still line them up against what
  you sent.

  **Mobiles only.** Landlines and foreign numbers are refused with `400 invalid_phone_number`
  naming the index and the exact string you sent. They are refused here rather than dialed
  and failed at the provider, because by then you have already been quoted a price per
  recipient.
</ParamField>

<ParamField body="text" type="string">
  What is spoken. Up to **1500 characters**, leading and trailing whitespace trimmed, read
  out as written. There is no SSML and no markup: punctuation is the only control you have
  over pacing.

  The text is synthesized once, before the response returns, and played to every recipient on
  the request. The response hands back an `audioId` for the result.

  Required unless you sent `audioId`.
</ParamField>

<ParamField body="audioId" type="string">
  A recording from an earlier response, played as-is. `aud_` followed by 24 lowercase hex
  characters.

  No synthesis happens, so the per-character recording charge is not incurred at all: a
  replay is the price of the calls and nothing else. Audio ids are scoped to your account and
  do not expire by default.

  Required unless you sent `text`.
</ParamField>

<ParamField body="voice" type="string">
  A voice alias from [`GET /v1/relay/voice/voices`](/api-reference/relay-voice/voices), for
  example `default`.

  Omit it to use the deployment's default voice. May only be sent alongside `text`. An alias
  that is not selectable answers `400 unknown_voice`.
</ParamField>

<ParamField body="callbackUrl" type="string">
  An **https** URL, up to 2048 characters, POSTed the finished job once every call has
  reached a terminal state. The body is the same shape this endpoint returns, so a callback
  and a status read never have to be reconciled.

  Two headers come with it:

  - `X-TriStack-Event: relay.voice.job.completed`
  - `X-TriStack-Signature: sha256=<hex>`, an HMAC-SHA256 over the exact bytes of the body

  Verify the signature before you act on the body. Without it a callback is an
  unauthenticated POST that anyone who learns your URL can forge.

  Plain `http` is refused with `400 invalid_callback_url`: the body names the people you
  called, and that is not a customer contact list to put on the wire in the clear.

  Delivery has two hard rules. Redirects are not followed, and a `3xx` counts as a failed
  delivery. Hosts that resolve to a private, loopback or metadata address are unreachable,
  checked at the socket against the resolved address rather than against the hostname, so no
  second DNS lookup can be swapped underneath it.

  The callback is attempted once. If your endpoint is down, the job is still finished and
  correct: read it from
  [`GET /v1/relay/voice/{jobId}`](/api-reference/relay-voice/job). Details on
  [Callbacks](/relay-voice/callbacks).
</ParamField>

<ParamField body="speed" type="number">
  How fast the voice reads the text, from **0.7** to **1.2**. Omit it and the call uses the
  project's tempo, set on the Relay Voice tab of the dashboard; omit that too and it uses the
  platform default of `1.0`, which is the voice's own natural pace.

  Below `1.0` is slower, which carries better on a poor line. Above is faster, which shortens
  the call. Extreme values are accepted but the speech quality falls off at both ends.

  A value outside the range is refused with `400 invalid_speed` rather than being quietly
  pulled back inside it, so a request that asks for `2.0` tells you the ceiling instead of
  sounding identical to `1.2`.

  Tempo does not change the price. You are billed per character synthesised and per answered
  call, and neither moves with speed, though a faster call does spend fewer seconds on the
  line.
</ParamField>

<ParamField body="reference" type="string">
  Your own id for this send, up to 128 characters. Stored, echoed back on every read of the
  job, and included in the callback body. Tristack never interprets it, so an order number, a
  campaign id or a row id all work.
</ParamField>

```json Replaying a recording you already paid for
{ "to": ["+91XXXXXXXXXX"], "audioId": "aud_9c11f0b3a4d75e2618ff0c7a" }
```

## What it costs

The wallet is held before anything is dialed and settled when the job finishes:

| | Held up front | Settled at the end |
|---|---|---|
| Calls | 40 paise for every recipient | 40 paise for every **answered** call |
| Recording | 3 paise per character, only when this request is the one preparing a new recording | The same amount, once |

A phone that rang out, was engaged or was refused costs nothing, so the debit is always at or
below the estimate and the difference goes back to the wallet.

<Note>
  Preparing a recording is free whenever the recording already exists. That covers a replay by
  `audioId` and, automatically, re-sending wording your account has already synthesized in the
  same voice: the same words resolve to the same `audioId` and skip the charge. The explicit
  id makes that guaranteed and visible rather than incidental.

  There is also a one-time ₹200 activation fee the first time Relay Voice is switched on for a
  project, charged on the dashboard toggle rather than here. It rents that project its own
  caller-id number. Switching the product off and on again is free; a second project is a
  second number and a second fee. See [Relay Voice pricing](/relay-voice/pricing).
</Note>

## Response

`202 Accepted`, with `Location: /v1/relay/voice/{jobId}`.

```json 202 Accepted
{
  "jobId": "rvj_3f2a17c9d0be45a7104ef2b8",
  "status": "Queued",
  "audioId": "aud_9c11f0b3a4d75e2618ff0c7a",
  "voice": "bella",
  "language": "en-IN",
  "recipients": 2,
  "estimatedCostPaise": 212,
  "costPaise": 0,
  "reference": "order-4417",
  "error": null,
  "createdAt": "2026-08-20T18:30:00Z",
  "completedAt": null,
  "calls": [
    {
      "callId": "rvc_9c11a4d75e2618ff0c7ab3f0",
      "to": "+91XXXXXXXXXX",
      "status": "Queued",
      "attempts": 0,
      "durationSeconds": null,
      "error": null,
      "costPaise": 0
    },
    {
      "callId": "rvc_2b8104ef3f2a17c9d0be45a7",
      "to": "+91YYYYYYYYYY",
      "status": "Queued",
      "attempts": 0,
      "durationSeconds": null,
      "error": null,
      "costPaise": 0
    }
  ]

```

<ResponseField name="jobId" type="string">
  `rvj_` plus 24 lowercase hex characters. Poll it at
  [`GET /v1/relay/voice/{jobId}`](/api-reference/relay-voice/job), and quote it to support.
</ResponseField>

<ResponseField name="status" type="string">
  `Queued` on the 202, because nothing has been dialed yet. The full set of job statuses is on
  the [job page](/api-reference/relay-voice/job#job-status).
</ResponseField>

<ResponseField name="audioId" type="string">
  The recording that will be played, `aud_` plus 24 lowercase hex characters. **Store it.**
  Sending it back in place of `text` replays these exact words with no synthesis and no
  per-character charge.
</ResponseField>

<ResponseField name="voice" type="string">
  The voice alias the recording was spoken in. On a replay it comes from the recording, not
  from the request, which is why `voice` cannot be sent with `audioId`.
</ResponseField>

<ResponseField name="language" type="string">
  The BCP-47 tag the voice is labelled with, for example `en-IN`. Informational: the voice
  itself decides how the words come out.
</ResponseField>

<ResponseField name="recipients" type="integer">
  How many phones will ring, after duplicates were collapsed. Compare it against the length of
  the `to` array you sent to see how many duplicates there were.
</ResponseField>

<ResponseField name="estimatedCostPaise" type="integer">
  The amount held on the wallet: every recipient at 40 paise, plus 3 paise per character if
  this request prepared a new recording. It is a ceiling, not a bill.
</ResponseField>

<ResponseField name="costPaise" type="integer">
  What has actually been charged. `0` until the job finishes, then the answered calls plus the
  recording charge. This field already includes the recording charge, so never add it on top.
</ResponseField>

<ResponseField name="reference" type="string | null">
  Your `reference`, or `null` if you did not send one.
</ResponseField>

<ResponseField name="error" type="string | null">
  `null` unless the job as a whole failed. Per-call problems live on the call, not here. The
  possible values are listed on the [job page](/api-reference/relay-voice/job#when-a-whole-job-fails).
</ResponseField>

<ResponseField name="createdAt" type="string">
  UTC ISO-8601 timestamp of when the job was accepted.
</ResponseField>

<ResponseField name="completedAt" type="string | null">
  UTC ISO-8601 timestamp of when the last call reached a terminal state. `null` until then.
</ResponseField>

<ResponseField name="calls" type="object[]">
  One entry per recipient, in the order the numbers first appeared in your `to` array.

  <Expandable title="call">
    <ResponseField name="callId" type="string">
      `rvc_` plus 24 lowercase hex characters.
    </ResponseField>

    <ResponseField name="to" type="string">
      The number in E.164, as it will be dialed. This is the normalized form, not the string
      you typed.
    </ResponseField>

    <ResponseField name="status" type="string">
      `Queued` on the 202. See the [call status table](/api-reference/relay-voice/job#call-status).
    </ResponseField>

    <ResponseField name="attempts" type="integer">
      Dial attempts made so far. `0` until the call is picked up by the dialer.
    </ResponseField>

    <ResponseField name="durationSeconds" type="integer | null">
      How long the answered call lasted. `null` until the provider reports an outcome, and on
      calls that were never answered.
    </ResponseField>

    <ResponseField name="error" type="string | null">
      A sentence explaining a failed call, for example that the provider refused it or never
      reported its outcome. `null` on everything else, including a phone that rang out.
    </ResponseField>

    <ResponseField name="costPaise" type="integer">
      What this one call cost: 40 paise once it is answered, `0` otherwise. It excludes the
      recording charge, which belongs to the job.
    </ResponseField>
  </Expandable>
</ResponseField>

<Note>
  Calls are dialed three at a time across the whole service, so a list of 200 numbers finishes
  over several minutes rather than at once. That limit is the provider's: one caller-id number
  placing hundreds of simultaneous calls is what gets the number blocked.
</Note>

## Errors

```json
{ "error": "A human-readable sentence.", "code": "snake_case_code" }
```

### Refused before anything is spent

| Status | `code` | What happened | What to do |
|---|---|---|---|
| 401 | `invalid_api_key` | The key is missing, malformed, unknown or revoked. | Check the header, or mint a new key. |
| 401 | `project_archived` | The key's project is archived. | Unarchive the project, or use a key from an active one. |
| 403 | `relay_voice_disabled` | Relay Voice is switched off on the project. | Turn it on for the project. The first time charges the one-time activation fee. |
| 403 | `insufficient_scope` | The key was not granted this capability | Create a key with the scope named in `requiredScope`. [Scopes](/platform/projects-and-keys#what-a-key-may-do) |
| 503 | `relay_voice_unavailable` | The operator switched the product off, or the deployment is missing its public base URL, call-provider credentials, speech credentials or any usable voice. Half configured is refused rather than half served. | Nothing you can fix in the request. Retry later or [contact support](mailto:support@tristack.tech). |
| 400 | `invalid_request` | `to` empty or over 500, both or neither of `text` and `audioId`, `text` over 1500 characters, `voice` sent with `audioId`, or `reference` over 128 characters. `error` names which. | Fix the field named in `error`. |
| 400 | `invalid_phone_number` | A number in `to` is not a dialable Indian mobile. `error` gives the index and the exact string you sent. | Fix that row. Landlines and foreign numbers cannot be dialed by this product. |
| 400 | `invalid_speed` | `speed` is outside 0.7 to 1.2, the range the speech provider accepts. Refused rather than clamped, so a request asking for 2.0 learns the ceiling instead of sounding like 1.2. | Send a value in range, or omit it to use the project's tempo. |
| 400 | `unknown_voice` | `voice` is not a selectable alias. A voice the operator has switched off answers identically. | Pick one from [`GET /v1/relay/voice/voices`](/api-reference/relay-voice/voices), or omit `voice` for the default. |
| 400 | `invalid_audio_id` | `audioId` is not shaped like one: `aud_` plus 24 lowercase hex characters. Checked before any lookup. | Copy the `audioId` from an earlier response rather than constructing one. |
| 400 | `invalid_callback_url` | `callbackUrl` is not an absolute https URL, or is over 2048 characters. | Use an absolute `https://` URL. |
| 404 | `audio_not_found` | No recording with that id on this account. Another account's id answers identically, on purpose, so a guessed id cannot be confirmed as real. | Use an `audioId` from one of your own earlier responses, or send `text` instead. |
| 410 | `audio_unavailable` | The recording is known but its stored audio is gone. | Send the `text` again. That makes a new recording, and the per-character charge applies to it. |
| 402 | `insufficient_balance` | The balance cannot cover the estimate. `requiredPaise` in the body is what this send needed, not your balance. | Top up, or send to fewer recipients. Nothing was dialed and nothing was charged. |

### Refused by the speech provider

These arrive after the hold is placed, while the text is being turned into audio. **Every one
of them releases the hold in full**, so a request that never produced audio costs nothing.

| Status | `code` | What happened | What to do |
|---|---|---|---|
| 502 | `text_rejected` | The speech provider would not synthesize this text, on length or on content. | Rewrite the text. Shorter and plainer is more likely to be accepted. |
| 502 | `voice_unavailable` | The configured voice or synthesis model no longer exists at the provider. | An operator problem, not yours. Try another voice and [tell support](mailto:support@tristack.tech). |
| 502 | `speech_provider_unauthorized` | The provider rejected our credentials. | Ours to fix. [Tell support](mailto:support@tristack.tech). |
| 502 | `speech_quota_exhausted` | The provider's quota is spent. | Ours to fix. [Tell support](mailto:support@tristack.tech). |
| 502 | `speech_provider_throttled` | The provider is rate limiting. | Retry shortly. |
| 502 | `speech_provider_error` | Any other synthesis failure, including a provider we could not reach. | Retry. If it persists, [tell support](mailto:support@tristack.tech). |

<Note>
  Synthesis runs on the request path on purpose. A text the provider refuses fails here, with
  a status code you can act on, instead of becoming a job that was accepted, charged for, and
  then quietly never spoken. It also means the provider's own error text stays in our logs:
  what comes back to you is a code and a plain sentence.
</Note>

Once a job is accepted, failures stop being status codes and become job state. See
[Get a job](/api-reference/relay-voice/job).
