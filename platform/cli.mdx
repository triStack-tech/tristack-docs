`tristack` manages your Tristack account from a shell, the way the AWS CLI manages an AWS
account. Anything you would otherwise click through on the dashboard (create a project, switch
on a product, mint an API key, set an SMS app name, add a test number, read the wallet) is one
command, and every command prints JSON.

It signs in with an [access token](/platform/access-tokens) (`tsa_...`), a long-lived
credential you make on the dashboard. It is not the API key your application sends to `/v1`
(`tsk_live_...`): the token manages the account, the key calls the products.

<Info>
  The CLI is written for scripts and for AI agents such as Claude Code and Codex as much as for
  people. [Using it from an AI agent](/platform/cli-agents) covers how to hand one a token
  safely.
</Info>

## Install

<Tabs>
  <Tab title="macOS and Linux">
    ```bash
    curl -fsSL https://tristack.tech/cli/install.sh | sh
    ```

    The installer needs Node.js 18 or newer and `curl` or `wget`. It puts the tool at
    `~/.local/bin/tristack`, with no `sudo`, and tells you the line to add to your shell
    profile if that folder is not on your `PATH`. Run it again to update.

    Set `TRISTACK_INSTALL_DIR` before running it to install somewhere else. The script runs
    only once it has downloaded in full, so a dropped connection installs nothing. It downloads
    over https only, into a fresh temporary folder that it always removes.
  </Tab>
  <Tab title="Windows">
    Install [Node.js](https://nodejs.org) 18 or newer, download
    [`tristack.mjs`](https://tristack.tech/cli/tristack.mjs), and run it with `node`:

    ```powershell
    node tristack.mjs --version
    ```

    Every command on this page works the same way with `node tristack.mjs` in place of
    `tristack`.
  </Tab>
</Tabs>

Check it runs:

```bash
tristack --version
```

```json
{
  "name": "tristack",
  "version": "0.1.0",
  "node": "22.22.1"
}
```

## Configure

<Steps>
  <Step title="Make an access token" icon="key">
    On the dashboard, open [Profile](https://tristack.tech/profile#access-tokens), **Access
    tokens**, and click **Create token**. Give it a name you will recognise later, such as the
    machine or agent it is for, and pick:

    - **Read only** or **Full access**. Read only can look at everything and change nothing.
    - An expiry: 7 days, 30 days, 90 days, 1 year or No expiry.

    The token is shown once. Copy it now. See [Access tokens](/platform/access-tokens) for what
    each choice means.
  </Step>
  <Step title="Save it" icon="floppy-disk">
    ```bash
    tristack configure
    ```

    Paste the token at the hidden prompt. It is checked against the API before it is saved, so
    a typo is caught here rather than on your first real command. Piped input is read as the
    token, so a secret manager can feed it without the token ever appearing on a command line:

    ```bash
    pass show tristack | tristack configure
    ```

    Piped, it first prints the address it is about to check the token against on stderr. It
    says where it saved the file (`savedTo`), and warns if that is inside a git working tree.
    With `--dry-run` it checks the token and saves nothing.
  </Step>
  <Step title="Check who you are" icon="user-check">
    ```bash
    tristack whoami
    ```

    It prints the account, your user, and the token in use with its name, scope and expiry.
  </Step>
</Steps>

<Warning>
  A token acts as you. Treat it like your password: never paste it into chat, a ticket or a
  commit. The CLI never takes it as a flag, because command-line arguments show up in process
  lists and shell history.
</Warning>

### Where the token comes from

The CLI looks for a token in this order and uses the first it finds:

1. The profile named by `--profile` on the command line.
2. The profile named by `TRISTACK_PROFILE`.
3. The environment variable `TRISTACK_ACCESS_TOKEN`. A value there that does not start with
   `tsa_` (a `tsk_` project key, say) is refused with exit code `3` and `invalid_token_format`
   before anything is sent.
4. The default profile: the one `tristack profiles use <name>` chose, otherwise the one
   called `default`.

A named profile wins over the environment's token, so pointing an agent at a Read only profile
really keeps it read only; when `TRISTACK_ACCESS_TOKEN` is also set, one warning line on stderr
says it was ignored. `tristack whoami` says which token it used, as `cli.source`: `env` or
`profile:<name>`.

**Where a token may go.** A token saved in a profile is only ever sent to the API address it
was saved (and checked) against. If `--api-url` or `TRISTACK_API_URL` names another host, the
command is refused with exit code `2` and `api_url_mismatch`, and nothing is sent. A token in
`TRISTACK_ACCESS_TOKEN` is only ever sent to `https://api.tristack.tech` or to this machine
(`localhost`, `127.0.0.1`, `::1`); any other host is refused with `env_token_host_refused`. A
`--dry-run` meets the same checks and fails the same way, so it never shows a plan aimed at a
host the real run would refuse.
Either way, for another host save a profile for it yourself:
`tristack configure --profile <name> --api-url <url>`. Do not trust an API URL taken from a
repository's files or a `.env`: one that an agent's shell loads could otherwise point your
token at someone else's server.

The config file is `~/.config/tristack/config.json` (under `$XDG_CONFIG_HOME` when that is
set), or `%APPDATA%\tristack\config.json` on Windows. It is written with mode `0600`, readable
only by you, and never through a symbolic link.

### Profiles

Keep several tokens side by side, for example one per account or one Read only and one Full
access, as named profiles:

```bash
tristack configure --profile work
tristack --profile work projects list
TRISTACK_PROFILE=work tristack projects list
tristack profiles
tristack profiles use work     # make it the default profile
```

`tristack profiles` lists the saved profiles, the API address of each and which one is
active, with the tokens masked. `tristack logout --profile work` forgets a profile and its
token, sending nothing. The token keeps working until it is revoked, so revoke it on the
Profile page too when it should stop working everywhere.

### Environment variables

| Variable | What it does |
|---|---|
| `TRISTACK_ACCESS_TOKEN` | Access token to use when neither `--profile` nor `TRISTACK_PROFILE` names a profile. Only sent to `https://api.tristack.tech` or this machine |
| `TRISTACK_PROFILE` | Profile to use when `--profile` is not given. Wins over `TRISTACK_ACCESS_TOKEN` |
| `TRISTACK_API_URL` | API base URL. `--api-url` wins over it; it wins over the profile's own, then `https://api.tristack.tech`. A profile's token is still only sent to the host it was saved for |
| `TRISTACK_PROJECT` | Default for `--project`, so a session about one project need not repeat it |
| `TRISTACK_API_KEY` | A project API key (`tsk_...`), used only by `tristack api` on `/v1/` paths |

## Commands

Run `tristack --help`, `tristack <command> --help` or `tristack <command> <subcommand> --help`
for the full usage of any command. Wherever a command takes a project, `--project` (or `-p`)
accepts the project's id or its name, and falls back to `TRISTACK_PROJECT`. A name is matched
exactly first, then ignoring case; when more than one project has it, the one that is not
archived is used, and if several are active the command asks for the id.
`projects create` is not idempotent: after a timeout, list the projects before trying again.

### Account and setup

| Command | What it does |
|---|---|
| `tristack configure` | Save an access token to a profile (reads it from stdin or a hidden prompt) |
| `tristack whoami` | Show the account, user and access token in use |
| `tristack profiles` | List the saved profiles (tokens shown masked) |
| `tristack profiles use <name>` | Make a saved profile the default one |
| `tristack logout [--profile <name>]` | Forget a profile and its saved token (revoke the token on the dashboard to stop it working) |
| `tristack account profile` | Show your profile (email, account, display currency) |
| `tristack agent-guide` | Print a Markdown guide for AI agents (setup, commands, output, safety) |
| `tristack version` | Print the version |

```bash
tristack account profile
```

### Projects

| Command | What it does |
|---|---|
| `projects list` | List your projects |
| `projects get <id\|name>` | Show one project and its product switches |
| `projects create <name>` | Create a project |
| `projects update <id\|name>` | Rename a project or switch its products on and off |
| `projects archive <id\|name>` | Archive a project (it stops serving and becomes read-only; restore undoes it) |
| `projects restore <id\|name>` | Restore an archived project |

`projects update` changes only the flags given: `--name`, `--manifold`, `--sms`, `--otp`,
`--voice`, `--email` and `--whatsapp` (each `on` or `off`), `--require-scoped-keys on|off`,
`--wallet-topup on|off`, `--topup-origins a,b` (replaces the list; `""` clears it),
`--voice-speed 0.7-1.2` (0 restores the default) and `--notify-email <address>` (`""` sends
reports to the account owner). There is no delete: archive a project instead.

The project can also be given as `--project <id|name>` (`-p`), and the new project's name as
`--name`. Give it once: an argument and a flag that disagree are refused, and nothing is sent.

```bash
tristack projects update "My app" --sms on --otp on
```

<Note>
  Switching Voice on for the first time charges the project's one-time activation fee to the
  wallet, so `--voice on` (and `tristack voice enable`) also needs `--yes`.
</Note>

### API keys

| Command | What it does |
|---|---|
| `keys list --project <p>` | List a project's API keys (hints only) |
| `keys create --project <p> <name> [--mode live\|test] [--scopes a,b]` | Create an API key; the full key is in the output once, store it at once |
| `keys revoke --project <p> <key id\|key name>` | Revoke an API key by id or by name |

Leave out `--scopes` for a key with full access. The scopes are `manifold:read`,
`manifold:invoke`, `manifold:embed`, `relay-email:send`, `relay-email:templates`,
`relay-email:domains`, `relay-email:suppression`, `relay-voice:send`, `relay-voice:read`,
`relay-voice:numbers`, `relay-whatsapp:send`, `relay-whatsapp:verify`, `relay-sms:send`,
`relay-sms:verify`, `relay-sms:read`, `verify:send`, `verify:check`, `verify:read`,
`wallet:read` and `wallet:topup`. `--mode` defaults to `live`. The new key is the `token`
field of the output; `tristack keys create --help` shows a one-liner that writes it straight
into `.env`.

```bash
tristack keys create --project "My app" backend --mode live
```

### Manifold models

| Command | What it does |
|---|---|
| `models list --project <p>` | List every Manifold model, with prices and whether the project allows it |
| `models set --project <p> <alias> [alias...]` | Allow only these models (replaces the whole list) |
| `models allow-all --project <p>` | Clear the list, so the project may call every enabled model |

```bash
tristack models set --project "My app" nova-lite haiku-4-5
```

### SMS

| Command | What it does |
|---|---|
| `sms show --project <p>` | Show a project's SMS settings: header, template, app name and its review |
| `sms enable` / `sms disable --project <p>` | Switch SMS on or off for a project |
| `sms app-name show --project <p>` | Show the approved app name, any name waiting for review, and the last one turned down |
| `sms app-name set --project <p> "<app name>" [--link <url>] [--template <id>]` | Ask for an app name (approved at once if it matches a verified domain, else reviewed) |
| `sms app-name withdraw --project <p>` | Withdraw the name waiting for review (the approved one stays) |
| `sms templates list --project <p>` | List the templates and which one the project uses |
| `sms templates use --project <p> <template id>` | Choose the template the project's codes use |
| `sms test-numbers list` | List the test numbers (shared by every project, at most 3) |
| `sms test-numbers add <phone>` | Add an Indian mobile number; it is sent a 6-digit code to confirm |
| `sms test-numbers confirm <id\|phone> <code>` | Confirm a test number with the code it received |
| `sms test-numbers resend <id\|phone>` | Send a test number a new code |
| `sms test-numbers remove <id\|phone>` | Remove a test number |
| `sms international show --project <p>` | Show the International SMS switch and the price per message by country |
| `sms international on` / `off --project <p>` | Allow or stop sending abroad |
| `sms dlt show --project <p>` | Show the project's DLT registration and its review state (change it on the dashboard) |

An app name is letters, numbers and single spaces, at most 30 characters. A new name needs
`--link` (your website or app-store listing) unless it matches a domain the account has
verified, see [Setting your app name](/relay-sms/index#setting-your-app-name).

```bash
tristack sms app-name set --project "My app" "Acme" --link https://acme.com
```

### OTP

| Command | What it does |
|---|---|
| `otp enable` / `otp disable --project <p>` | Switch OTP on or off for a project |
| `otp test send --project <p> --to <phone\|email> [--channel sms\|whatsapp\|email\|voice] --yes` | Send one real code to a phone number or email address (charged to the wallet) |
| `otp test check --project <p> <verification id> <code>` | Check the code a test verification received |

`otp test send` goes through the same path as `POST /v1/relay/otp`, with the project's
switches, prices and limits, and is charged like any send.

```bash
tristack otp test send --project "My app" --to +919876543210 --yes
```

### Email

| Command | What it does |
|---|---|
| `email enable` / `email disable --project <p>` | Switch Email on or off for a project |
| `email domains list --project <p>` | List the project's sending domains and their DNS records |
| `email domains add --project <p> <domain>` | Claim a sending domain; the output has the CNAME records to publish |
| `email domains verify --project <p> <domain>` | Look the domain's records up in DNS now and report what is wrong |
| `email domains remove --project <p> <domain>` | Give up a sending domain (no undo; re-adding issues new records) |
| `email analytics --project <p> [--window 24h\|7d\|30d]` | Deliveries, bounces and complaints over a window |
| `email templates list --project <p>` | List the project's email templates |

```bash
tristack email domains add --project "My app" mail.acme.com
```

### Account domains

The account's website domains. A verified one approves a matching SMS app name at once, and
is shared by every project.

| Command | What it does |
|---|---|
| `domains list` | List the account's domains, verified or waiting |
| `domains add <domain>` | Add a domain; the output has the TXT record that proves it |
| `domains verify <id\|domain>` | Check the domain's TXT record now (also approves a waiting app name it matches) |
| `domains remove <id\|domain>` | Remove a domain (a name already approved through it stays approved) |

```bash
tristack domains verify acme.com
```

### Wallet, billing and the identity check

| Command | What it does |
|---|---|
| `wallet balance` | Show the wallet balance |
| `wallet transactions [--limit <n>] [--before <iso-time>]` | List wallet transactions, newest first (`--limit` 1 to 100) |
| `wallet ledger [--page <n>] [--page-size <n>] [--search <text>]` | The wallet ledger grouped the way the dashboard shows it |
| `billing show` | Show the billing details |
| `billing set -f key=value...` | Change billing details: the fields given replace the current ones |
| `kyc status` | Show the state of the account's identity check for SMS |

`billing set` takes `entityType` (`Business` or `Individual`), `legalName`, `pan`, `gstin`,
`addressLine1`, `addressLine2`, `city`, `stateCode` (the two-digit GST state code, `29` for
Karnataka; `billing show` lists them under `states`), `postalCode` and `phone`, with `-f` or
`--data`. Any other field name is refused before anything is sent. It reads the current
details first, so only the fields you give change; the first save needs `legalName`,
`addressLine1`, `city`, `stateCode`, `postalCode` and `phone` together. A refusal names the
field in `details.field`.

Top-ups, automatic top-ups and submitting the identity check are done by a person on the dashboard. See
[what a token cannot do](/platform/access-tokens#what-a-token-cannot-do).

```bash
tristack billing set -f legalName="Acme Pvt Ltd" -f gstin=27ABCDE1234F1Z5
```

### Voice and numbers

| Command | What it does |
|---|---|
| `voice voices` | List the voices calls can be spoken in |
| `voice enable --project <p> --yes` | Switch Voice on for a project (the first time charges the activation fee) |
| `voice disable --project <p>` | Switch Voice off for a project |
| `numbers list` | List the account's rented numbers |
| `numbers available [--prefix <digits>]` | Search numbers that can be rented (renting one is done on the dashboard) |

```bash
tristack numbers available --prefix 9180
```

### Usage and logs

| Command | What it does |
|---|---|
| `usage summary` | Totals per project, product and day |
| `usage events` | The line items behind the totals, newest first |
| `usage rates` | Every rate currently charged |
| `logs` | Request log: every billable event, newest first (same as `usage events`) |

`usage summary`, `usage events` and `logs` filter with `--project`, `--product` (`sms`,
`otp`, `email`, `voice`, `manifold`, `embeddings` or `all`; the API's own ids such as
`relay_sms` work too), `--status` (`all`, `succeeded`, `failed` or `provider_error`), `--from`
and `--to` (`yyyy-mm-dd`, both inclusive: `--to` counts that whole day, and the answer writes
it as the start of that day). `usage events` and `logs` also page with `--page`, `--page-size`
and `--search`. An unknown `--product`, `--status` or `--window` is refused (exit code `2`,
`invalid_value`) rather than quietly read as a default. WhatsApp is not in the usage report;
its charges are in `tristack wallet ledger`.

```bash
tristack logs --project "My app" --status failed --page-size 20
```

## Anything else: tristack api

`tristack api` calls any API path with your credentials, like `gh api`, so anything the
dashboard can do and no command covers yet is still one line:

```bash
tristack api GET /api/v1/projects
tristack api PATCH /api/v1/projects/<id> -F relaySmsEnabled=true
tristack api GET /api/v1/usage/events -f product=manifold -f pageSize=10
```

- The method defaults to `GET`, or `POST` when a body is given.
- `--data` sends a JSON body: inline, `@file` to read a file, or `-` to read stdin.
- `-f key=value` (`--raw-field`) adds a string field. `-F key=value` (`--field`) adds a typed
  one: `true`, `false`, `null`, numbers and JSON stay typed, and `@file` reads a file. For a
  `GET` they become the query string. `a.b=1` nests and `a[]=x` appends to an array.

Paths under `/api/v1/` use the access token. Paths under `/v1/`, the product endpoints, take a
project API key from `TRISTACK_API_KEY` instead, because an access token is never accepted
there:

```bash
TRISTACK_API_KEY=tsk_live_... tristack api POST /v1/manifold/messages --data @request.json
```

## Output and exit codes

Every command prints JSON on stdout, so it pipes straight into `jq`:

```bash
tristack projects list | jq -r '.[] | select(.status == "Active") | .name'
```

A call with no response body prints `{"ok": true, "status": 204}`. An answer from an API path
that is not JSON (most often the website's page, because the API URL is wrong) is an error,
`unexpected_response` with exit code `1`, so stdout never carries anything but JSON; audio
files are the one exception. `tristack configure` saves a profile only after the API's own
answer about the token.

A few lists are a bare array (`projects list`, `keys list`, `wallet transactions`); the rest
sit under a named key beside their counts, for example `domains` in `domains list`, `numbers`
in `sms test-numbers list`, and `events` (with `page`, `pageSize`, `total` and `totalPages`)
in `usage events`. Amounts are in paise in fields ending in `Paise`; model prices are rupees
per million tokens (`inrPerMTokIn`). Times are ISO 8601 in UTC. `tristack agent-guide` lists
every shape.

A failure exits non-zero, and the last line on stderr is the error. `code` is the API's own
[error code](/platform/errors) where there is one; branch on it, not on `error`. Lines before
it, which can also appear when a command succeeds, carry a `level` (`warning` or `info`), such
as `{"level": "warning", "warning": "TRISTACK_ACCESS_TOKEN is set but ignored: ..."}`:

```json
{"status":403,"code":"token_read_only","error":"This access token is read only. Create one with full access to make changes."}
```

The fields are `status` (the HTTP status, `null` when nothing reached the server), `code`,
`error`, and, when they apply, `retryAfter` (seconds, on a `429`) and `details`.

| Exit code | Meaning |
|:---:|---|
| `0` | Success |
| `1` | API error: validation, not found, conflict, limits |
| `2` | Usage error: a bad command or flag. Nothing was sent |
| `3` | Auth error: no token, a token refused or expired, `token_read_only`, `session_required`, `token_location_blocked`, `token_ip_blocked` |
| `4` | Network error: nothing reached the server, safe to retry |

On a `429 rate_limited`, wait `retryAfter` seconds before trying again.

## --dry-run and --debug

`--dry-run` prints the request a command would make and sends nothing:

```bash
tristack projects create "My app" --dry-run
```

```json
{
  "dryRun": true,
  "method": "POST",
  "url": "https://api.tristack.tech/api/v1/projects",
  "auth": "access token",
  "body": {
    "name": "My app"
  }
}
```

A dry run may still read: a command that names a project turns the name into an id first, and
`billing set` reads the current details it builds on. It never writes, and that includes your
own config file: `configure`, `logout` and `profiles use` with `--dry-run` say what they would
do and change nothing.

A dry run of a command that costs money says so, with the price: `voice enable` and
`projects update --voice on` add `"charges"` and `"chargesPaise"` (the one-time activation
fee, or nothing if the project has paid it before) and `"needsYes": true`; `otp test send`
adds the price of the code it would send. A dry run of a change made with a Read only token
adds `"wouldBeRefused"`, because the real run would get `token_read_only`.

`tristack agent-guide` lists every dashboard API path the commands use, with the commands
that use it, for anything you want to call directly with `tristack api`.

`--debug` logs each request and response to stderr as JSON lines (method, URL, status, time
taken and the bodies), with every credential masked: the access token or API key it sends,
and any new key, token or signing secret in a response, such as the key `keys create` prints
once. The JSON on stdout is unchanged, so a script can keep reading it, and it is the one
place a new key is shown in full.
