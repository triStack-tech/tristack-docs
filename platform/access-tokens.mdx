An **access token** lets the [`tristack` CLI](/platform/cli), a script or an AI agent manage
your Tristack account without a browser. It does what you can do on the dashboard, as you,
with a few exceptions kept for a person who is signed in.

It is not an API key. The two never stand in for each other:

| | Access token | API key |
|---|---|---|
| Looks like | `tsa_...` | `tsk_live_...` or `tsk_test_...` |
| Belongs to | You, the person who made it | One project |
| Made on | Dashboard, Profile, Access tokens | The project's API keys |
| Accepted on | The dashboard API, `/api/v1/...` | The product endpoints, `/v1/...` |
| For | Managing the account: projects, keys, settings, the wallet, usage | Calling Manifold AI and Tristack CPaaS from your application |

An access token sent to a `/v1` product endpoint is refused with `401 invalid_api_key`. An API
key is not a way into the dashboard API: sent to `/api/v1`, it gets a bare `401` with no body.
The one exception is the Voice number endpoints (`/relay/voice/numbers` and
`/relay/voice/compliance`), which answer on both prefixes and take either credential. Tokens
are never accepted by Tristack's operator console.

## Making one

Sign in to the dashboard, open [Profile](https://tristack.tech/profile#access-tokens),
**Access tokens**, and click **Create token**. Choose:

- **A name**, 1 to 64 characters. Name it after the machine or agent that will hold it
  (`laptop`, `claude-code-ci`), so the list tells you what to revoke later.
- **Access**: Read only or Full access. See [scopes](#scopes).
- **Expiry**: 7 days, 30 days, 90 days, 1 year, or No expiry.
- **Location**: whether to email you when it is used from a new place (on unless you turn it
  off), and optionally the countries or IP addresses it may be used from. See
  [location alerts and locks](#location-alerts-and-locks).

Your email address must be verified first. The token is shown **once**, on the screen that
follows; Tristack keeps only a hash of it and can never show it again. Lose it and you make a
new one. Tristack also emails you that a token was created, with its name, access, expiry and
the IP address and country it was created from, so a token nobody meant to make does not go
unnoticed.

The list on the same page shows each token's name, access, a hint (`tsa_AbCd...wxyz`, its
first and last four characters), when it was made, when it was last used and when it
expires. An expired token stays listed, marked expired, until you revoke it.

## Format

`tsa_` followed by 43 characters of base64url, made from 32 random bytes. Send it as a bearer
token:

```bash
curl https://api.tristack.tech/api/v1/projects \
  -H "Authorization: Bearer $TRISTACK_ACCESS_TOKEN"
```

No other header is needed. The CLI does this for you.

## Scopes

| Access | Can do | Refused with |
|---|---|---|
| **Read only** (`read`) | `GET` only: read projects, keys (as hints), settings, the wallet, usage, logs | `403 token_read_only` on anything that changes something |
| **Full access** (`full`) | Everything you can do on the dashboard, except the session-only actions below | `403 session_required` on those |

Pick Read only whenever the job is to look: reporting, checking settings, reading logs for a
failed send. A leaked Read only token can show your account to someone, but cannot change it.

### What a token cannot do

Some actions need you, signed in to the dashboard, whatever the token's scope. A token gets
`403 session_required` on:

- **Access tokens themselves**: making, listing, revoking them and changing their location
  settings. A token cannot make another token, so revoking one is always final, and it cannot
  loosen its own locks.
- **Signing in and out**: sign-out, Google sign-in, and the forgot-password and
  reset-password steps.
- **The identity check for SMS (KYC)**: submitting it and deleting it. The consent has to be
  your own. A token can read its status.
- **Automatic top-ups**: every change to them, including saving a payment method.
- **Legal declarations**: submitting the SMS DLT registration
  (`POST /api/v1/relay/sms/dlt/submit`) and the Voice number compliance documents
  (`POST /api/v1/relay/voice/compliance`). A project API key can still submit the Voice
  documents on `/v1/relay/voice/compliance`.

Billing details and the International SMS switch stay open to Full access tokens.

Top-ups themselves are paid in the browser, through Razorpay Checkout, so in practice they are
done on the dashboard too.

## Expiry and revocation

A token with an expiry stops working at that moment, with `401 access_token_expired`. One
with No expiry works until you revoke it.

To revoke one, click **Revoke** beside it on the Profile page. It stops working on its next
request, with `401 invalid_access_token`, the same answer as a token that never existed.
Revoking cannot be undone. Revoking from a token is not possible, by design: that is a
session-only action.

Resetting your password revokes **every** access token on the account, and the "password
changed" email says how many. It also signs out every dashboard session on every device.
Whoever had the old password, or a session they took over, may have made a token, and a reset
is how you take the account back. Make new tokens afterwards for
the machines and agents that need them.

## Location alerts and locks

Each token has three settings, on the Profile page under **Access tokens**: open a token's
**Edit** beside its location summary, or set them when you create it.

| Setting | Default | What it does |
|---|---|---|
| **Email me when this token is used from a new location** | On | Emails you when the token is used from a network or a country it has not been used from before, and when one of the locks below refuses a request |
| **Only allow from these countries** | Off (any country) | Refuses requests from every other country, with `403 token_location_blocked` |
| **Only allow from these IP addresses** | Off (any address) | Refuses requests from outside the listed addresses and ranges, with `403 token_ip_blocked` |

**Alerts.** A "network" is the block an address belongs to: the first three parts of an IPv4
address (a /24) or the first three groups of an IPv6 one (a /48), so a home connection or a
phone that changes address within its provider does not set one off. The very first place a
token is used from is its setup and sends nothing. You get at most one email an hour per token:
anything that happens in between waits and comes in the next email, all together. Each email
names the token, and for every new place or refused request, the IP address, the country, the
time and the program that sent it (the CLI identifies itself as `tristack-cli/<version>`). If it
was not you, revoke the token.

**Country lock.** Pick countries from the list. A request whose country is not known
(`XX`) or that comes through the Tor network (`T1`) is refused too, unless you add "Unknown
country" or "Tor network" to the list. If you lock a token to countries, make sure your own
country is in the list: the dashboard suggests it.

**IP address lock.** Up to 20 entries, one per line: single addresses (`203.0.113.7`,
`2001:db8::1`) or ranges in CIDR notation (`203.0.113.0/24`, `2001:db8::/32`). Use it for a
server or an office with a fixed address.

A refused request does nothing at all: it changes nothing, is not counted against the limits,
and does not update `lastUsedAt`. The answer says where it came from, so you can tell whether
it was you:

```json
{
  "error": "This access token cannot be used from this country. Its owner limited it to certain countries on the Profile page at tristack.tech.",
  "code": "token_location_blocked",
  "ip": "198.51.100.4",
  "country": "DE"
}
```

Changes apply from the token's next request. Only a signed-in person can change them
(`PATCH /api/v1/account/access-tokens/{id}`), never a token.

**Where it was used.** **Locations** under each token lists every network it was used from in
the last 90 days: the country, the last address, when it was first and last seen, and how many
requests came from it. A row is one network, shown with the latest country seen for it. The
request count and "last seen" are written every few minutes, so they can trail the true figures
by up to 5 minutes. Tristack keeps each row until 90 days after the token was last used from
it. `tristack whoami` shows the token's locks and the address and country the API sees you at.

## Limits

| Limit | Value | When it is reached |
|---|---|---|
| Live tokens per person | 10, counting neither revoked nor expired ones | `409 too_many_tokens` on create. Revoke one you no longer use |
| Requests | 300 a minute per person, across all their tokens | `429 rate_limited`, with a `Retry-After` header and `retryAfter` in the body, in seconds |
| Failed tokens | 30 a minute from one IP address: unknown, revoked, expired or malformed tokens | `429 rate_limited` for every token from that address for the rest of the minute, without the token being checked. A valid token never counts towards it |

Requests made from a signed-in dashboard session are not counted against the 300.

`lastUsedAt` is updated at most once a minute per token, so it can trail the true last use by
up to a minute.

## Errors

The envelope is the same as everywhere else on the API, `{ "error": "...", "code": "..." }`:
branch on `code`. A `401` also carries `WWW-Authenticate: Bearer error="invalid_token"`. A
value that is not an access token at all (a `tsk_` key, a typo) is not read as one: it gets the
dashboard's bare `401` with no body, which is why the CLI checks for the `tsa_` prefix first.

| `code` | Status | What happened | What to do |
|---|:---:|---|---|
| `invalid_access_token` | 401 | The token is unknown, malformed or revoked. All three answer the same, so a guessed token cannot be confirmed as real | Check the value. If it was revoked, make a new one |
| `access_token_expired` | 401 | The token's expiry has passed | Make a new one on the Profile page |
| `account_disabled` | 401 | Tristack has disabled the account. Every token and session of the account is refused | Write to hello@tristack.tech. A new token will not help |
| `token_read_only` | 403 | A Read only token sent something other than `GET` | Use a Full access token for changes |
| `session_required` | 403 | The action is one only a signed-in person can take. See [what a token cannot do](#what-a-token-cannot-do) | Do it on the dashboard yourself |
| `token_location_blocked` | 403 | The token is locked to certain countries and this request came from another one, or from an unknown country or Tor. Nothing was done. The body has the request's `ip` and `country` | If it was you, add the country on the Profile page. If not, revoke the token |
| `token_ip_blocked` | 403 | The token is locked to certain IP addresses and this request came from outside them. Nothing was done. The body has the request's `ip` and `country` | If it was you, add the address on the Profile page. If not, revoke the token |
| `rate_limited` | 429 | Over 300 requests in a minute across your tokens, or over 30 failed tokens in a minute from one IP address | Wait `Retry-After` seconds, then retry |
| `too_many_tokens` | 409 | You already have 10 live tokens | Revoke one, then create again |
| `email_unverified` | 403 | Creating a token from an account whose email address is not verified | Verify it from the link in the email, or resend the link from the dashboard |
| `invalid_name` | 400 | The name is empty or longer than 64 characters | Send 1 to 64 characters |
| `invalid_scope` | 400 | `scope` is not `read` or `full` | Send one of the two |
| `invalid_expiry` | 400 | `expiresInDays` is not 7, 30, 90, 365 or `null` | Send one of those |
| `invalid_countries` | 400 | A country lock names something that is not a two-letter country code | Use codes such as `IN` or `US`, or `XX` and `T1` |
| `invalid_ips` | 400 | An IP lock entry is not an address or a CIDR range, or there are more than 20 | Fix the entry the message names |
| `not_found` | 404 | Revoking or changing a token that is unknown, already revoked or someone else's | Nothing to change |
| `not_a_token` | 404 | `GET /api/v1/account/access-tokens/current` was called from a session, not a token | Call it with a token |

The last eight come from managing tokens, which the dashboard does for you; you meet them only
if you call those endpoints from your own signed-in code. Every code is also on
[Errors](/platform/errors#access-token-codes).

## Checking a token

`GET /api/v1/account/access-tokens/current`, called with a token, describes the token making
the call. It is what `tristack whoami` and `tristack configure` use:

```json
{
  "id": "6b1f0c2e-4d7a-4a51-9a63-0e5d8f2b7c11",
  "name": "laptop",
  "scope": "full",
  "hint": "tsa_AbCd...wxyz",
  "createdAt": "2026-11-07T09:30:00Z",
  "expiresAt": "2027-02-05T09:30:00Z",
  "lastUsedAt": "2026-11-07T09:31:00Z",
  "expired": false,
  "alertNewLocations": true,
  "allowedCountries": ["IN"],
  "allowedIps": [],
  "user": { "email": "you@example.com", "name": "Your Name" },
  "accountName": "Acme",
  "caller": { "ip": "203.0.113.7", "country": "IN", "countryName": "India" }
}
```

`expiresAt` and `lastUsedAt` are `null` when the token never expires or was never used.
`allowedCountries` and `allowedIps` are empty when there is no lock. `caller` is where this very
request came from, as the locks see it.

Two cases look alike and are not. `XX` ("Unknown country") is a country Cloudflare could not
tell; a lock admits it only when "Unknown country" is on the list. A request with no country at
all (`"country": null`, which `tristack whoami` shows as "not provided") reached the API without
Cloudflare's country header; a token with a country lock refuses it, whatever the list says.
Requests to `api.tristack.tech` always pass through Cloudflare, so you should only see that
when testing locally.

## Keeping tokens safe

- Treat a token like your password. It acts as you.
- One token per machine or agent, named after it, so revoking one stops exactly one thing.
- Read only unless the job needs to change something, and an expiry unless it truly must run
  unattended for good.
- Keep it in an environment variable or a secret manager, never in a repository, a chat or a
  command line.
- Lock a token on a server to that server's address, and keep new-location alerts on.
- Revoke a token when the work it was made for is done, and at once if it may have leaked.
