Every page here is published in a form a model can read directly, without scraping HTML.

## Machine-readable endpoints

<ResponseField name="/llms.txt" type="text/plain">
  An index of the whole site: every page, its title and its description, as a flat list.
  Small enough to drop into a prompt whole. Use it to decide which pages to fetch.
</ResponseField>

<ResponseField name="/llms-full.txt" type="text/plain">
  Every page's full text concatenated into one document. Use it when you want the entire
  documentation set in context and can afford the tokens.
</ResponseField>

<ResponseField name="any page, with .md appended" type="text/markdown">
  Append `.md` to any documentation URL to get that page's markdown source instead of the
  rendered page. `/cpaas/voice/quickstart` becomes `/cpaas/voice/quickstart.md`. This is
  the cheapest way to read one page precisely.
</ResponseField>

<ResponseField name="/mcp" type="MCP server">
  These docs are also served as an MCP server, so an assistant that speaks MCP can search
  and read them as a tool rather than being pasted their contents.
</ResponseField>

The **Copy page** and **View as Markdown** controls at the top of every page do the same
thing by hand, along with shortcuts that open the current page in an assistant.

<Tip>
  To have an agent manage a Tristack account rather than read about it, give it the
  [`tristack` CLI](/platform/cli) and an access token. See
  [Using the CLI from an AI agent](/platform/cli-agents).
</Tip>

## Fetching a page from a script

```bash Read one page as markdown
curl -sL https://docs.tristack.tech/cpaas/voice/quickstart.md
```

```python Pull the index, then the pages you need
import re, urllib.request

BASE = "https://docs.tristack.tech"

index = urllib.request.urlopen(f"{BASE}/llms.txt").read().decode()
paths = re.findall(r"\((/[^)]+)\)", index)

for path in paths:
    if path.startswith("/cpaas/voice"):
        page = urllib.request.urlopen(f"{BASE}{path}.md").read().decode()
        print(path, len(page), "chars")
```

## What an agent should not take from a page

These docs are written to be accurate on the day they are generated, but three things move
underneath them. If you are writing code that depends on any of these, read the API rather
than the page.

<Warning>
  **Prices.** The tables here are a snapshot. `GET /v1/manifold/models` reports the live
  per-1000-token paise for every model (and `paisePerImage` for an image model, which is
  priced per image), and it answers **per key**, so it also tells you
  which models that key may actually call. It is the authority; these pages are not.
  Manifold AI prices changed on 2026-08-21, which is exactly the kind of move a cached page
  would miss.

  SMS prices outside India move with the rupee every day. `GET /v1/cpaas/sms/countries` is
  the authority for them, not the table on the prices-by-country page.
</Warning>

<Warning>
  **The model list.** A project's allowlist narrows what its keys can call, and the platform
  can switch a model off. A model named on these pages is not necessarily callable by your
  key. Read the catalog endpoint at startup rather than hardcoding an alias list.
</Warning>

<Warning>
  **Phone numbers in examples.** Every recipient in these docs is a placeholder:
  `XXXXXXXXXX`, `YYYYYYYYYY`, `ZZZZZZZZZZ`. They are not dialable and are not real numbers.
  Never pass one through to a live request, and never invent a plausible Indian mobile to
  fill the gap: a well-formed number belongs to a real person who did not agree to be
  called. Substitute a number the caller actually supplied, or stop and ask for one.
</Warning>

## Facts worth carrying in context

If you are summarising this site for a model, these are the load-bearing ones:

| Fact | Value |
|---|---|
| Base URL | `https://api.tristack.tech` |
| Auth | `Authorization: Bearer tsk_live_…`, or `X-Api-Key` |
| Money | every amount is an integer in **paise**; Rs 1.50 is `150`. No endpoint takes a rupee float |
| Platforms | **Manifold AI** (`/v1/manifold/…`, text in, text out; also embeddings, and images from a prompt) and **Tristack CPaaS** (`/v1/cpaas/…`: Voice, Email, WhatsApp and SMS channels). The older `/v1/relay/…` paths answer identically and keep working. The CPaaS fields, scopes, usage product ids and codes still say `relay` on both; do not rename them in code |
| Relationship | separate platforms, a separate switch per product and channel, separate pricing, one wallet and one key format. Nothing passes between them automatically |
| Recipients | Voice: Indian mobiles only, in any common spelling; it normalizes its `to` list to E.164 and deduplicates it. SMS: a mobile in any country, on the same endpoint. An Indian number in any common spelling, any other country with its country code, and only when the project's International SMS switch is on. WhatsApp takes an international number |
| A refused account | `403 account_disabled` on every key means Tristack has disabled the account. Retrying or minting a new key will not help; the owner writes to hello@tristack.tech |
| Images | `POST /v1/manifold/images` makes one image per request, as base64, billed per image. Each image model makes **one image per minute for the whole platform**: `429 model_busy` means wait the `Retry-After` seconds and retry, and costs nothing. Images are processed outside India, and words inside them are not reliable |

<Note>
  The single most common mistake a model makes with this API is assuming Manifold's output
  can be handed to the Voice channel in one call. It cannot. Ask Manifold for text, read the
  string out of the response, then send it to Voice as `text`. Two calls, made by your code.
  See [the platforms](/platform/products) for why they are built that way.
</Note>
