<Update label="2026-11-07" description="Access tokens and the tristack command-line tool">

  **Manage your account from a shell, or let an AI agent do it.** The new `tristack` CLI does
  what the dashboard does (projects, product switches, API keys, SMS app names and test
  numbers, OTP, email domains, the wallet, billing details, usage and logs) as commands that
  print JSON. It is built for scripts and for coding agents such as Claude Code and Codex. See
  [Command line](/platform/cli) and [Using the CLI from an AI agent](/platform/cli-agents).

  - Install it with `curl -fsSL https://tristack.tech/cli/install.sh | sh` (Node.js 18 or
    newer), then run `tristack configure`. `tristack agent-guide` prints a guide written for
    agents.
  - It signs in with an **access token** (`tsa_...`), made on the dashboard's Profile page under
    Access tokens: Read only or Full access, expiring after 7, 30, 90 or 365 days or never,
    and shown once. See [Access tokens](/platform/access-tokens).
  - A token works on the dashboard API (`/api/v1/...`) only. Your application's calls to
    `/v1/...` still take a project API key (`tsk_...`), unchanged.
  - Some actions stay with a signed-in person: managing access tokens, signing in and out,
    password reset, submitting or deleting the identity check, and changing automatic top-ups.
  - At most 10 live tokens per person, and 300 requests a minute across them.
  - New error codes: `401 invalid_access_token`, `401 access_token_expired`,
    `403 token_read_only`, `403 session_required`, and `429 rate_limited` on the dashboard API.
    See [errors](/platform/errors#access-token-codes).
  - Dashboard API text with a NUL character (U+0000) in it is now refused with
    `400 invalid_text` naming the field, instead of failing with a `500`. A refused billing
    profile now also names its field, in `field`.
  - In the CLI, a profile named with `--profile` or `TRISTACK_PROFILE` wins over
    `TRISTACK_ACCESS_TOKEN`. A token saved in a profile is only sent to the API address it was
    saved for, and a token in `TRISTACK_ACCESS_TOKEN` only to `https://api.tristack.tech` (or
    this machine).
  - A test number whose code could not be sent is no longer kept, so adding it again works.
  - **Location alerts and locks, per token.** You get an email when a token is used from a new
    network or country (at most one an hour), and you can lock a token to countries or to IP
    addresses: a request from anywhere else is refused with `403 token_location_blocked` or
    `403 token_ip_blocked`, and you are emailed about it. Each token's recent locations are on the
    Profile page. Making a token emails you too, and a password reset revokes every token. See
    [location alerts and locks](/platform/access-tokens#location-alerts-and-locks).

</Update>

<Update label="2026-11-07" description="App names approved through your domain, and an identity check for SMS">

  **An app name that matches your verified domain is approved at once.** Verify your website's
  domain in the dashboard, and an app name that matches it skips the review. See
  [Instant approval through your domain](/relay-sms/index#instant-approval-through-your-domain).

  - To verify a domain, add it on the project's SMS tab, publish one TXT record at the domain
    itself (host `@`, value `tristack-verification=...`) and click Check now. A domain already
    verified for Email counts with no TXT record. Verified domains are shared by every project
    in the account.
  - The app name matches when, without spaces and capitals, it is the domain's own name without
    hyphens: "Acmebooks" and "Acme Books" match `acmebooks.com` and `acme-books.in`;
    "Acmebooks Pro" does not.
  - A matching name is approved as you save it, or, if it is already waiting, as the domain's
    check succeeds. Blocked names are still refused. A name that contains a bank's or a large
    brand's name, and any name Tristack rejected or revoked on any project in the account, in
    any spelling, still goes to review.
  - Nothing changes in the API.

  **A second template under Tristack's header.** `TRK_OTP_3` ("123456 is your requested OTP
  for Acmebooks - Powered by Tristack Technologies") can be picked under SMS template on the
  project's SMS tab. `TRISTKDEFAULT2` stays the default. Both carry your approved app name and
  cost the same. See [the templates](/relay-sms/index#in-india-you-do-not-need-a-dlt-registration).

  **Accounts that send under Tristack's header now go through an identity check.** The first
  approved app name in an account starts 30 days. After them, until the check is verified, codes
  under Tristack's header and abroad are limited to 200 in any 24 hours across the account. Codes
  under your own DLT header are not affected. See
  [Identity check (KYC)](/relay-sms/index#identity-check-kyc).

  - The check is on the dashboard's Profile page: your legal name, PAN and, if you have one,
    GSTIN, checked by a person at Tristack. No documents to upload.
  - Accounts with an app name approved before today have their 30 days from today.
  - New error code: `429 kyc_daily_limit`, with a `Retry-After` header. Nothing is charged.

</Update>

<Update label="2026-11-06" description="SMS reaches any country, on the same endpoint">

  **SMS codes to numbers outside India.** `POST /v1/relay/sms/otp` now takes a mobile number in
  any country. Your integration does not change: the same request body, the same verify and
  status calls. Write the number with its country code and the country code decides the route.
  Indian numbers go out exactly as before, under DLT, at 40 paise. See
  [Numbers in India and abroad](/relay-sms/index#numbers-in-india-and-abroad).

  - **One switch per project, International SMS**, on the project's SMS tab in the dashboard.
    It is off by default, because codes to numbers abroad are the usual target of SMS pumping.
    Indian numbers do not need it.
  - **Priced per country**, from the provider's price for that country in US dollars at the
    day's exchange rate, so prices abroad move with the rupee. The list is on
    [SMS prices by country](/relay-sms/countries), and live at the new
    [`GET /v1/relay/sms/countries`](/api-reference/relay-sms/countries) (scope
    `relay-sms:read`).
  - A number abroad receives Tristack's fixed text, not your DLT template, from a sender that
    depends on the country. `header` is `null` for it, and delivery reads `unknown`, because
    there are no delivery reports outside India yet.
  - At most 300 messages outside India per project in any 24 hours, on top of the existing
    limits.
  - The send and status responses carry a new field, `country`, the recipient's ISO code
    (`IN` for India).
  - New error codes: `403 international_sms_disabled`, `503 international_sms_unavailable`,
    `400 sms_country_unavailable` and `502 recipient_opted_out`. `invalid_phone_number` now
    also covers landlines, premium-rate, toll-free and shared-cost numbers abroad. See
    [errors](/platform/errors).
  - Tristack is not sending SMS outside India yet. Until it is, every number abroad answers
    `503 international_sms_unavailable` and nothing is charged. The switch can be turned on
    now.

  **Every code names your app.** Codes under Tristack's shared header now always use the
  template that carries your app name ("123456 is your requested OTP for YourApp. Best
  Regards, Tristack Technologies LLP Team."), and codes abroad name it too. Tristack reviews
  every app name before it reaches the public. See
  [Setting your app name](/relay-sms/index#setting-your-app-name).

  - Set the name on the project's SMS tab with a link to your website or your app's store
    listing. Names of banks, payment apps, government bodies, telecoms and large brands are
    refused on the spot.
  - While the name waits for review, codes go only to the account's test numbers (up to three
    Indian mobiles, added and confirmed on the SMS tab) and carry the name waiting for review.
    Any other number answers the new `403 app_name_pending`.
  - An approved name is fixed. A different name is a new request, and the approved one keeps
    sending until the new one is approved.
  - `400 app_name_required` now means the project has no approved name and none waiting for
    review. Nothing is charged for either refusal.
  - Projects already sending were given their project name as app name where it fits the
    rules, and app names already in use were kept as approved. A project with its own DLT
    registration is not affected.

</Update>

<Update label="2026-11-05" description="Manifold AI speaks the OpenAI Chat Completions format">

  **Use any OpenAI client with Manifold.** `POST /v1/chat/completions` and `GET /v1/models`
  accept your Tristack key and answer in OpenAI's format, with tools and streaming. Point the
  OpenAI SDK, LiteLLM or an agent framework at `https://api.tristack.tech/v1` and use a Manifold
  model alias as the model. It runs on the same pipeline as `POST /v1/manifold/messages`: the
  same models, allowlist, wallet billing and usage records, at the same price. See
  [OpenAI-compatible API](/manifold/openai-compatible).

</Update>

<Update label="2026-10-21" description="Relay is now Tristack CPaaS, and disabled accounts are refused">

  **New names, same API.** Tristack Relay is now **Tristack CPaaS**, and its channels are
  called by their own names: **Voice**, **Email**, **WhatsApp** and **SMS**. Manifold is now
  **Manifold AI**. Nothing you call has changed: every path (`/v1/relay/...`), request field,
  scope, error code and usage product id keeps `relay`, and these pages keep their addresses.
  The website's `/relay` pages moved to `/cpaas`, and the old links redirect.

  What reads differently:

  - Error sentences name the channel, for example "Voice is not enabled for this project."
    rather than "Relay Voice is not enabled for this project.". The `code` beside each one is
    unchanged, which is why you should branch on `code` and never on `error`.
  - Wallet ledger descriptions do the same: `Voice: …`, `Email: …`, `SMS: one OTP`,
    `WhatsApp: one OTP` and `Voice activation for <project name>`.
  - The bounce, complaint and stopped-webhook emails link to **Open Email settings**.

  **Accounts Tristack disables are refused everywhere**

  - Every API key of a disabled account answers `403 account_disabled`, before any project or
    product check. Signing in to the dashboard, with a password or with Google, answers `403`
    with the same code, a session already open answers `401` with it on its next request, and
    no password reset goes through. Write to hello@tristack.tech.
  - Work accepted before the disable stops too. A queued Voice job checks before every call it
    places: calls not yet placed end `Cancelled`, calls already ringing finish, and the job
    ends `Failed` with `account_disabled`. The speech charge stands, since the recording was
    made, and a `callbackUrl` still receives the finished job. A video or audio embedding job
    ends `failed` with `account_disabled`, with nothing charged and its reservation released.
  - Automatic top-ups never charge a disabled account, and a charge waiting in its notice
    window is stood down. Rented numbers keep renewing, so a number is not lost to a disable.
  - Archiving a project now stops its queued Voice jobs in the same way, with
    `project_archived` on the job.
  - An archived project is read-only for its owner. Every change to it, or to anything filed
    under it, answers `409 project_archived` and writes nothing. Restoring it and revoking its
    keys still go through, as does stopping a rented number's renewal. A `PATCH` that archives
    a project and changes something else in the same request answers
    `400 archive_with_changes`. [Archiving a project →](/platform/projects-and-keys#archiving-a-project)

  See [errors](/platform/errors) and [job status](/api-reference/relay-voice/job).

  **Corrections and smaller changes**

  - A rented number is used as the caller id only once Tristack support has assigned it to a
    project, on request. Until then calls go out from the shared Tristack number. The pages
    that said renting alone changed the caller id are corrected.
    [Phone numbers →](/relay-voice/numbers)
  - The one-time Rs 200 Voice activation is not a phone number. A few pages still said it
    rented one, and no longer do.
  - Meta bills you separately for WhatsApp messages; the pages no longer say it bills per
    conversation.
  - SMS is in early access: ask us to switch it on through the [contact form](https://tristack.tech/company#contact).
  - The dashboard API's rate limit of 10 requests a minute now applies only to signing in,
    registering and the password and verification routes. Signed-in account routes, such as
    reading your profile, are no longer limited.
  - A DLT entity or template that is suspended stays suspended even if its header is later
    reported approved.
  - [Errors](/platform/errors) now lists every SMS and WhatsApp code, and the Email and Voice
    codes it was missing.

</Update>

<Update label="2026-08-31" description="Relay Voice calls are free, and you can rent your own number">

  **Calls are no longer metered.** `pricePerCallPaise` is `0`. Every call, in every outcome,
  now costs nothing, and speech is the only per-use charge Relay Voice has: 3 paise per
  character, once, when a recording is prepared.

  What this changes for you:

  - A send that replays an existing recording is **completely free**. It takes no hold, makes
    no debit and leaves no row in the ledger, so such a send works on an empty wallet. If you
    reconcile Relay Voice jobs against wallet transactions, expect jobs with no matching rows.
  - `estimatedCostPaise` now equals the final `costPaise` rather than being a ceiling, because
    the only charge is known before the first phone rings. Nothing comes back at settlement.
  - `costPaise` on an individual call is `0` in every state, including `Completed`. Summing
    that column no longer tells you anything about your bill; count statuses to measure reach.
  - Broadcasting got dramatically cheaper and personalizing did not. One 65-character message
    to 500 people is Rs 1.95, where it was Rs 201.95. Five hundred personalized messages are
    unchanged at Rs 1,065. See [reusing a recording](/relay-voice/reusing-audio).
  - The one-time Rs 200 activation per project is unchanged, but it never was a phone number
    and the docs no longer say it was.

  `pricePerCallPaise` stays on `GET /v1/relay/voice/voices` and on usage rows. Read it rather
  than hardcoding the zero.

  **Rent your own number**

  - `GET /v1/relay/voice/numbers/available`, `POST /v1/relay/voice/numbers` and
    `PATCH /v1/relay/voice/numbers/{id}` search for, rent and stop renewing an Indian number,
    so calls go out from your number instead of a shared one. Keys need the new
    `relay-voice:numbers` scope.
  - **Rs 236 per number per month**, as Rs 200 plus Rs 36 GST, shown split on the ledger. This
    is the only recurring charge on the platform.
  - Indian numbers are sold only to registered businesses. Verify once per account through
    `POST /v1/relay/voice/compliance` with an incorporation and a GST certificate; a person
    reviews it over a few days.
  - **There is no grace period.** The renewal is decided the day before it falls due, and a
    wallet that cannot cover it, or auto-renew left off, releases the number permanently. The
    account owner is warned by email seven, three and two days before, the last landing a day
    ahead of the decision.
  - New error codes: `compliance_required`, `compliance_pending`, `compliance_exists`,
    `number_unavailable`, `document_too_large`, `unsupported_document_type`. See
    [phone numbers](/relay-voice/numbers).

</Update>

<Update label="2026-08-22" description="Embedded top-up window and automatic top-ups">

  Two new ways to put money in the wallet. Both credit the same account balance every
  product spends from, and neither changes how a request is priced, held or settled.

  **Top up from your own app**

  - `POST /v1/wallet/topup-sessions` mints a single-use permit from your backend, and your
    page opens a Tristack-hosted top-up window with it, so the account holder adds money
    without ever coming to the dashboard. The permit expires in fifteen minutes and rides in
    the URL fragment, so it never reaches a server log.
  - `GET /v1/wallet` reads the balance with the same project API key: `balancePaise`,
    `minTopUpPaise`, `lowBalance`, and where automatic top-up stands. Amounts are integer
    paise as everywhere else, so Rs 100 is `10000`.
  - Both need switching on per project in the dashboard, with at least one allowed origin.
    See [Top up from your own app](/platform/embedded-topup).

  **Automatic top-ups**

  - Set a threshold on the Wallet page in the dashboard and the wallet refills itself from a
    saved payment method. Dashboard only, never the API-key surface.
  - A charge is never immediate. RBI's e-mandate framework requires notice before every
    recurring debit, so a tripped threshold sends an email and the charge follows roughly
    24 hours later. Size the threshold to cover about a day of your own spend, or the refill
    lands after the outage instead of before it.
  - Manual top-ups are unaffected whether automatic top-ups are unavailable, off or
    suspended. See [Automatic top-ups](/platform/auto-topup).

</Update>

<Update label="2026-08-21" description="Manifold prices corrected to the published rate">

  <Warning>
    **Manifold prices went up by about 11 percent.** Relay Voice is unaffected, and no past
    usage was re-billed.
  </Warning>

  The deployment was running an older set of rates than the published ones, so calls were
  being billed about 10 percent under the published price. It now bills the published
  rates, which is what `GET /v1/manifold/models` has always been the authority for.

  The tables on these pages were wrong in the other direction, and listed prices about
  10 percent under what was actually charged. They have been regenerated and now match the
  endpoint.

  What this means for you:

  - `nova-micro` input moves from 0.35 to **0.38** paise per 1000 tokens, output from 1.39
    to **1.54**. Other models move by the same proportion.
  - Read `GET /v1/manifold/models` if you display or budget against prices. It reports the
    per-1000-token paise for every model your key can call, and it is the authority. These
    tables are a snapshot.
  - Nothing about the request or response shape changed.

</Update>

<Update label="2026-08-21" description="Relay Voice documented, pages reorganised">

  Relay Voice is documented here for the first time, and these pages were rebuilt around
  two products instead of one. Nothing in the Manifold API changed with this entry: what
  moved is the documentation.

  **Relay Voice**

  - `POST /v1/relay/voice` takes Indian mobile numbers and either `text` to speak or an
    `audioId` to replay, and answers `202` with a `jobId`. The calls are dialled in the

  - Pricing: ₹200 once per project the first time Relay Voice is switched on, then
    40 paise per answered call and 3 paise per character of newly synthesized speech.

<Update label="2026-08-17" description="First public release of the documentation">

  First public release of the documentation, describing Tristack Manifold as it runs today.

  **API surface**

  - `POST /v1/manifold/messages`: text and image messages, optional `system` prompt,
    `max_tokens` (default 4096, cap 65536), `temperature`, `top_p`, `stop_sequences`, and
    `stream` for server-sent events.
  - `GET /v1/manifold/models`: the catalog with per-model rates in paise per 1000 tokens.
  - API-key authentication on both, as `Authorization: Bearer tsk_...` or `X-Api-Key`.

  **Catalog**

  - 54 aliases across 19 families, converted at 90.0 INR per USD.
  - Five aliases are switched off on this deployment: `opus-5`, `opus-4-8`, `sonnet-5`,
    `sonnet-4-6` and `haiku-4-5`. Account-level access is still being finalised, so
    `GET /v1/manifold/models` does not list them and a call answers `400 unknown_model`,
    the same answer a misspelt alias gets. The other 49 serve normally.
  - 21 aliases accept image blocks. The list is on the [models page](/manifold/models).

  **Billing**

  - Prepaid wallet per account, in integer paise, minimum top-up 10000 paise (₹100).
  - Hold before the call, settle on real token usage afterwards, difference returned.
  - Failed calls cost nothing. A client abort mid-stream settles, for the whole input
    estimate plus whatever output had been delivered.

  **Documentation**

  - Getting started, authentication, streaming, vision, the full API reference, the error
    catalog, the model catalog, the billing model and how to get support.
  - Model and price tables are generated from a captured `GET /v1/manifold/models`
    response, so they match the deployment they were captured from.

</Update>
